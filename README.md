# 现场巡检问题标注

A small prototype of an on-site inspection loop:

1. Unity AR detects a horizontal plane, places a marker, and submits an issue.
2. A Go API stores the issue in SQLite.
3. A React page lists issues and changes their status.

The same JSON fields are used by all three parts.

```json
{
  "id": "iss_…",
  "title": "入口墙面破损",
  "description": "左侧墙体存在裂缝",
  "priority": "high",
  "status": "open",
  "position": { "x": 0.42, "y": 0.03, "z": 1.26 },
  "createdAt": "2026-10-29T12:40:00Z",
  "updatedAt": "2026-10-29T12:40:00Z"
}
```

`id`, `status`, `createdAt`, and `updatedAt` are generated by the server. A new issue is always `open`. Timestamps are UTC RFC3339, with fractional seconds. `priority` is `low`, `medium`, or `high`. `position` is the marker in the current AR session, in meters. It is not GPS, and it is not restored onto the physical world after the app restarts.

## API

Default listen address: `:8787`. Database file: `server/data/issues.db` (created on startup). CORS allows any origin.

| Method | Path | Body | Success |
| --- | --- | --- | --- |
| `GET` | `/health` | | `200 {"status":"ok"}` |
| `GET` | `/api/issues` | | `200 {"issues":[...]}` newest first. Empty is `{"issues":[]}`. |
| `POST` | `/api/issues` | see below | `201` the created issue |
| `GET` | `/api/issues/{id}` | | `200` one issue |
| `PATCH` | `/api/issues/{id}` | `{"status":"open"\|"in_progress"\|"resolved"}` | `200` the updated issue |
| `DELETE` | `/api/issues/{id}` | | `204` empty body |

Create body:

```json
{
  "title": "入口墙面破损",
  "description": "左侧墙体存在裂缝",
  "priority": "high",
  "position": { "x": 0.42, "y": 0.03, "z": 1.26 }
}
```

`description` may be omitted. `priority` is stored lowercase (`HIGH` is accepted and saved as `high`). Client-supplied `id`, `status`, and timestamps are ignored.

Errors are JSON: `{"error":"..."}`.

| Situation | Status | `error` |
| --- | --- | --- |
| Empty title | 400 | `title is required` |
| Priority not low/medium/high | 400 | `priority must be low, medium, or high` |
| Missing position | 400 | `position is required` |
| Bad JSON | 400 | `invalid JSON` |
| Status not open/in_progress/resolved | 400 | `status must be open, in_progress, or resolved` |
| Unknown id | 404 | `issue not found` |

Title max 200 characters. Description max 4000.

## Start the Go API

```bash
cd server
go test ./...
go run ./cmd/server
```

Override the address or database with flags or environment variables: `-addr` / `ADDR`, `-db` / `DB_PATH`.

The process listens on all interfaces, so a phone on the same network can reach it.

### curl: create, list, update, and restart

From another terminal, with the server running in `server/`:

```bash
curl -s http://127.0.0.1:8787/health

curl -s -X POST http://127.0.0.1:8787/api/issues \
  -H 'Content-Type: application/json' \
  -d '{"title":"入口墙面破损","description":"左侧墙体存在裂缝","priority":"high","position":{"x":0.42,"y":0.03,"z":1.26}}'

curl -s http://127.0.0.1:8787/api/issues

curl -s -X PATCH http://127.0.0.1:8787/api/issues/REPLACE_WITH_ID \
  -H 'Content-Type: application/json' \
  -d '{"status":"in_progress"}'
```

Validation:

```bash
curl -s -X POST http://127.0.0.1:8787/api/issues \
  -H 'Content-Type: application/json' \
  -d '{"title":"  ","priority":"high","position":{"x":0,"y":0,"z":0}}'

curl -s -X POST http://127.0.0.1:8787/api/issues \
  -H 'Content-Type: application/json' \
  -d '{"title":"裂缝","priority":"urgent","position":{"x":0,"y":0,"z":0}}'

curl -s -X PATCH http://127.0.0.1:8787/api/issues/REPLACE_WITH_ID \
  -H 'Content-Type: application/json' \
  -d '{"status":"done"}'
```

Persistence: stop the server (Ctrl+C) and start it again with `go run ./cmd/server`. `GET /api/issues` still returns the same rows. The file is `server/data/issues.db`. `go test ./...` also reopens a temp database and reads the row back.

Optional Docker (Go + a SQLite volume):

```bash
docker compose up --build
```

The API is on port 8787. The database lives in the `inspection-data` volume at `/data/issues.db`.

## Start the React admin

```bash
cd web
npm install
npm run dev
```

Open http://127.0.0.1:43123 . The page loads issues from `VITE_API_BASE` (default `http://127.0.0.1:8787`, see `web/.env`). The address box can point at another host; it is saved in `localStorage`.

The list shows title, priority, and status (plus description, position, and timestamps). Status buttons send `open`, `in_progress`, or `resolved`. Filters are client-side. If the API is down, the page shows an error banner and a retry button instead of a blank screen.

Production build: `npm run build`.

## Unity on a real device

This repository cannot launch the Unity Editor or an AR phone. Plane detection has to be checked on an ARCore or ARKit device. The scripts and project settings below are what you open in Unity.

### Open the project

1. Install **Unity 6000.3 LTS** (6000.3.27f1 or another 6000.3 patch) with **Android Build Support** (SDK, NDK, OpenJDK) and/or **iOS Build Support**.
2. In Unity Hub, **Add project from disk** and choose the `unity/` folder. The first open downloads the packages in `Packages/manifest.json` and needs network access.
3. Wait for the console line `Inspection: project settings ready`. That editor script (`Assets/Editor/InspectionProjectSetup.cs`) sets:
   - Android IL2CPP, ARM64, minimum API 29, internet permission, bundle id `com.inspection.armarker`
   - iOS camera usage text and minimum iOS 15
   - **Allow downloads over HTTP = Always Allowed** (Android cleartext and iOS ATS, so the phone can call `http://` on your LAN)
   - Active Input Handling = Both
   - ARCore loader on Android and ARKit loader on iOS
4. If that line never appears, use the menu **Inspection → Apply Project Settings**, then **Edit → Project Settings → XR Plug-in Management** and enable **ARCore** (Android tab) and **ARKit** (iOS tab). Install the Android/iOS modules first; the Android tab is hidden until the Android module exists.
5. Open **Project Settings → XR Plug-in Management → Project Validation** and clear any red errors it reports. Those checks know the exact SDK level for the package you imported.
6. Open `Assets/Scenes/Main.unity`. It contains one `Inspection` object. On play, that object builds the AR session, XR Origin, plane manager, raycast manager, and the report form.

### Point the phone at the Go server

`localhost` on the phone is the phone, not your computer.

1. Run the Go server on the computer. Leave port **8787** open on the LAN firewall.
2. Put the phone and the computer on the same Wi-Fi. Find the computer's LAN IP (for example `ipconfig` / `ip addr`).
3. On the device, set **后端地址** to `http://192.168.x.x:8787` (your IP, not `127.0.0.1`). The field is saved in PlayerPrefs, so later launches keep it. A scheme-less value such as `192.168.x.x:8787` is treated as `http://`.
4. Tap **测试连接**. The banner should say the backend connected. The default written into the scene is `http://192.168.0.10:8787`; change it.
5. If you need a different default before building, select **Inspection** in `Main.unity` and edit `Backend Base Url`, or edit `BackendConfig.DefaultBaseUrl`.

Cleartext HTTP is required for this prototype because the Go server does not serve TLS. The editor script sets **Allow downloads over HTTP** to **Always Allowed**, which is Unity's switch for Android `usesCleartextTraffic` and iOS App Transport Security. If a build still blocks HTTP, set it by hand: **Edit → Project Settings → Player → Other Settings → Allow downloads over HTTP → Always Allowed**, for both Android and iOS. Do not ship that setting in a production app.

### What to do on the phone

1. Allow the camera permission.
2. Move the phone slowly over a floor or table until a horizontal plane appears (blue mesh).
3. Tap the plane. A cube marker is placed at the hit. Taps on the form, buttons, or text fields do not place a marker.
4. Enter a title (required), an optional description, and a priority, then tap **提交问题**.
5. A green banner with the new id means the server saved it. A red banner shows the validation or network error. After a successful save the marker is colored by priority: green low, yellow medium, red high.
6. Open the React page and change the status.

Editor Play Mode does **not** show a camera feed or detect planes. A click in the Game view places a marker 1.5 m in front of the camera so you can try the form against the API. The status line says so. That path is not a substitute for a device test.

Build with **File → Build Profiles** (or Build Settings): Android for ARCore, iOS for ARKit. Android target architecture is ARM64 and the scripting backend is IL2CPP. The scene `Assets/Scenes/Main.unity` is already in the build list.

## Done

- Unity scripts: horizontal plane detection, tap-to-place marker, report form, success and failure feedback, UI clicks ignored, on-device backend URL, cleartext HTTP setting.
- Go API: health, create, list, get, update status, delete, validation, CORS, SQLite persistence, `go test`.
- React admin: list, status change, error state, status/priority filters, delete.

## Not done

- No run inside the Unity Editor and no install on a physical AR phone in this environment. Device plane detection still has to be confirmed by whoever opens the Unity project.
- Markers are not reloaded onto the same physical surfaces after the Unity app restarts.
- No accounts, photos, or floor-plan view.
- No automated compile of the C# scripts (there is no Unity in this environment).

## Known issues

- The phone must use the computer's LAN IP. `127.0.0.1` only works for the React page on that same computer.
- Positions are local to that AR session. Closing the app and scanning the room again will not put old cubes back on the same cracks.
- The editor fallback marker is only for trying the HTTP form.
- XR loader assignment uses an internal editor API (`GetOrCreate`). If a future XR Plug-in Management release renames it, enable ARCore and ARKit from Project Settings by hand.
- If one AR Foundation property does not compile on a different 6.x package, the Unity console names the line. The two most version-sensitive calls are `ARCameraManager.autoFocusRequested` and `XROrigin.RequestedTrackingOriginMode`.
- Android min SDK is set to 29. If Project Validation asks for a higher level, follow that window.
- Vulkan versus OpenGLES3 is left at the Unity default. If the camera background is black on a specific phone, enable OpenGLES3 in Player Settings and try again.
- `go test` covers the API and a database reopen. It does not boot Unity.
